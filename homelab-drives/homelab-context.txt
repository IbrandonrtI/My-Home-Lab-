==== 5. STORAGE DESIGN ====

NOTE (2026-10-22): the text in this section up to 5A describes the single-drive setup of 2026-10-20 (label STORAGE, mounted directly at /mnt/storage). 5A at the end of this section is the current design and wins wherever they differ.

principle: [VERIFIED] databases and app files on the boot drive; bulk data on the data drive. Each service has its own folder. Never point FileBrowser at /mnt/storage itself.
why ext4: it is a Linux filesystem, so Docker and Postgres get real permissions, and it is not left "dirty" after an unplug like NTFS.
boot drive: Hitachi 750GB, device sda, LVM (vgmint-root, vgmint-swap_1). UUIDs are in the report; the drive letter can change.
data drive: Toshiba MQ01ABD100 1 TB, ext4, UUID 0f029dec-c289-4d9a-b893-8ea5ef2817bc, 916 GB usable (created with mkfs.ext4 -L STORAGE -m 0, so no 5 percent reserve). Until 2026-10-22 it was labelled STORAGE and mounted directly at /mnt/storage. Since 2026-10-22 it is labelled MAIN1, mounted at /mnt/disks/MAIN1, and /mnt/storage is a mergerfs pool on top of it (see 5A). 61G used on 2026-10-22. The text below that says STORAGE or mounted at /mnt/storage describes the 2026-10-20 state.
letters change: [VERIFIED] always use the UUID or the label (/dev/disk/by-label/MAIN1 since 2026-10-22), never sdb. On 2026-10-20 at about 19:37 local, lsblk showed the letters had SWAPPED: Toshiba data drive = sda (sda1 at /mnt/storage), Hitachi boot drive = sdb (sdb1 at /boot/efi). The report (taken earlier) had the opposite. Wherever this file says sda for the boot drive and sdb for the data drive, that is the report-time state only. 5A. DRIVE POOLS AND DAILY BACKUP (added 2026-10-22)

source: TROUBLESHOOTING.md section 2 (Steps 1 to 8) and Phase 15; README.md section 3 and appendix 19; the scripts/ folder (also in README appendix 19). All [VERIFIED] by output Brandon pasted on 2026-10-22 unless tagged otherwise.

design
- Two mergerfs pools. Main: /mnt/storage (labels MAIN1, MAIN2, ...). Backup: /mnt/backup (labels BACKUP1, ...). Each drive is plain ext4 mounted by UUID at /mnt/disks/<LABEL>. mergerfs, not RAID: a failed drive loses only its own files.
- Pool fstab line type is fuse.mergerfs (plain mergerfs rejected nofail). Options: allow_other,cache.files=off,category.create=mfs,moveonenospc=true,dropcacheonclose=true,nofail,fsname=mergerfs-<role>,x-systemd.requires-mounts-for=<each branch>. The pool fails closed when a branch is missing. Mount points are locked with chattr +i while unmounted.
- wait-for-hdd.conf (Wants/After mnt-storage.mount) is unchanged because /mnt/storage is still mnt-storage.mount. Containers need a restart after any remount (sudo hdd-recover).
- No stack was edited: the pool takes over the path /mnt/storage.

the three tools (source in scripts/, SHA256 in scripts/SHA256SUMS)
- sudo drives: menu and status. Subcommands: version, status, adopt, recover, power, test-setup N SIZE, test-cleanup. Menu option 2 connects a new drive (main or backup), option 3 disconnects one, option 5 converts a single drive into a pool. Safety: boot drive and the current data drive are protected; busy drives refused; typed device name plus ERASE to format; typed REMOVE for the last backup drive; the last main drive cannot be removed; removing a drive from a pool first copies its files to the other drives (2 rsync passes, then verify); fstab snapshot and rollback. Test mode DRIVES_TEST=1 uses image files and /mnt/test-main, /mnt/test-backup, /mnt/test-disks and its own fstab. It keeps its pools mounted until sudo DRIVES_TEST=1 drives test-cleanup. drives power: main -B 254 -S 0, backup -B 254 -S 120 (10 min idle). OWNER default brandon (env DRIVES_OWNER). Log: /var/log/homelab-drives.log.
- sudo hdd-recover: wrapper for drives recover.
- sudo homelab-backup: dumps the Nextcloud database (db-dumps/nextcloud-<date>.sql.gz, about 2 MB), rsync -aH --numeric-ids --delete --backup --backup-dir=<dest>/_deleted/<date>/main of the main pool into <dest>/main, copies config files with -aHR into <dest>/boot-configs (etc, home, opt, usr, var, root-crontab.txt; 1.1 GB), deletes dumps and _deleted folders older than 30 days. Guards: source pool mounted and not empty; at least 20 GB free at the destination; first run needs pool size plus 20 GB; a missing drive cannot empty the backup. Config file /etc/homelab-backup.conf is sourced after the defaults and can override CONFIG_PATHS and DEST_FALLBACK. Status file /var/lib/homelab-backup/last-run; log /var/log/homelab-backup.log.

schedule
- Root crontab (4 lines, Appendix B.4): drives power at boot; load-cycle log of MAIN1 at 6:00; boot-drive APM 254 at boot; homelab-backup at 6:00 every day.
- First manual run: started 2026-10-22 19:04, finished 19:28, OK in 1420 s, /mnt/storage and the copy both 61G. [PENDING] The first scheduled run is 2026-10-23 06:00: ask for sudo drives status (Last backup line) or sudo tail -20 /var/log/homelab-backup.log.

restore
- Copy files out of the backup with cp -a (or rsync) into /mnt/storage, never edit inside the backup. Then for Nextcloud: docker exec -u www-data nextcloud php occ files:scan --all. Deleted or replaced files are in _deleted/<date>/ for 30 days.

B.11 The inventory script prodesk-full-report.sh (read-only; masks secret-looking settings; run with sudo bash ~/prodesk-full-report.sh)
-----
cat > ~/prodesk-full-report.sh <<'EOF'
#!/bin/bash
U=${SUDO_USER:-brandon}
OUT=/home/$U/prodesk-full-report.txt
HP=/home/$U/homepage-config
sec() { echo; echo "=================== $1 ==================="; }
mask() { sed -E '/^[[:space:]]*-?[[:space:]]*[A-Za-z0-9_.-]*(pass|secret|token|key|auth|user|deviceid)[A-Za-z0-9_.-]*[[:space:]]*[:=]/I s/([:=][[:space:]]*).*/\1***MASKED***/'; }
BOOT=$(lsblk -no pkname "$(findmnt -no SOURCE /boot/efi)" 2>/dev/null)
{
sec "SYSTEM"; hostnamectl | head -8; grep PRETTY_NAME /etc/os-release; ls /usr/share/xsessions 2>&1; uptime -p; timedatectl | grep "Time zone"
sec "HARDWARE"; dmidecode -s system-product-name 2>&1; lscpu | grep -E "Model name|^CPU\(s\)"; free -h | head -2
dmidecode -t memory 2>/dev/null | grep -E "^\s+(Size|Speed|Locator):" | grep -v "No Module"
sec "DRIVES: layout"; lsblk -o NAME,SIZE,ROTA,MODEL,TRAN,FSTYPE,LABEL,UUID,MOUNTPOINTS
sec "DRIVES: space"; df -hT -x tmpfs -x devtmpfs -x squashfs -x efivarfs
sec "DRIVES: fstab"; grep -v '^#' /etc/fstab | grep -v '^$'
sec "DRIVES: mount point and folders"; lsattr -d /mnt/storage 2>&1; ls -la /mnt /mnt/storage 2>&1; ls -la /usr/local/bin 2>&1
sec "DRIVES: health"
echo "-- boot drive /dev/$BOOT"; smartctl -i -H -A /dev/$BOOT 2>&1 | grep -E "Device Model|Model Family|User Capacity|Rotation|overall-health|Power_On_Hours|Load_Cycle|Reallocated_Sector|Current_Pending|Temperature"; hdparm -B /dev/$BOOT 2>&1 | tail -1
echo "-- storage drive (label MAIN1; the inventory script in TROUBLESHOOTING section 5 has an extra STORAGE POOLS AND BACKUP part)"; smartctl -i -H -A -d sat /dev/disk/by-label/MAIN1 2>&1 | grep -E "Device Model|User Capacity|Rotation|overall-health|Power_On_Hours|Load_Cycle|Reallocated_Sector|Current_Pending|Temperature"; hdparm -B "/dev/$(lsblk -no pkname "$(readlink -f /dev/disk/by-label/STORAGE)")" 2>&1 | tail -1
sec "SYSTEMD AND CRON"; cat /etc/systemd/system/docker.service.d/*.conf 2>&1; for s in docker tailscaled ssh anydesk lightdm; do echo "$s: $(systemctl is-active $s 2>&1)"; done; echo "systemd-resolved enabled: $(systemctl is-enabled systemd-resolved 2>&1)"
echo "-- root cron"; crontab -l 2>&1 | grep -v '^#'; echo "-- load cycle log"; tail -5 /var/log/loadcycles.log 2>&1; echo "-- hdd-recover"; cat /usr/local/bin/hdd-recover 2>&1
sec "NETWORK AND DNS"; ip -4 -br addr; cat /etc/resolv.conf; ss -tulpn | grep ':53 '; ufw status 2>&1 | head -2; nslookup google.com 192.168.1.198 2>&1 | tail -4
sec "REMOTE ACCESS SETTINGS"; grep -E "^Handle" /etc/systemd/logind.conf 2>&1; grep -h -E "^autologin" /etc/lightdm/lightdm.conf /etc/lightdm/lightdm.conf.d/* 2>&1; cat /etc/apt/sources.list.d/docker.list 2>&1
sec "DOCKER"; docker --version; docker compose version; docker info 2>/dev/null | grep -E "Docker Root Dir|Storage Driver"
echo; docker compose ls -a 2>&1; echo; docker ps -a --format 'table {{.Names}}\t{{.Image}}\t{{.Status}}\t{{.Ports}}'
echo; docker image ls --format 'table {{.Repository}}\t{{.Tag}}\t{{.Size}}'; echo; docker volume ls
sec "DOCKER: versions"; for c in $(docker ps -aq); do docker inspect -f '{{.Name}}  {{index .Config.Labels "org.opencontainers.image.version"}}' $c; done
sec "DOCKER: mounts and restart policy"
for c in $(docker ps -aq); do docker inspect "$c" --format '== {{.Name}} | restart: {{.HostConfig.RestartPolicy.Name}} | network: {{.HostConfig.NetworkMode}}{{println}}{{range .Mounts}}   {{.Source}} -> {{.Destination}} ({{if .RW}}rw{{else}}ro{{end}}){{println}}{{end}}'; done
sec "DOCKER: which drive each container sees"
for c in immich_server filebrowser-filebrowser-1 nextcloud homepage; do echo "-- $c"; docker exec "$c" df -h /data /srv/hdd /srv/750GB_HDD /mnt/storage 2>/dev/null; done
sec "PORTAINER STACK FILES (secrets masked)"
for f in $(find /var/lib/docker/volumes/portainer_data/_data/compose -maxdepth 2 -type f 2>/dev/null | sort); do echo "### $f"; mask < "$f"; echo; done
sec "TAILSCALE"; tailscale version | head -1; tailscale ip -4; tailscale status --peers=false 2>&1 | head -3; tailscale dns status 2>&1 | head -15; tailscale serve status 2>&1
sec "ADGUARD HOME CONFIG"; awk '/^http:/,/^users:/' /opt/adguard-docker/conf/AdGuardHome.yaml 2>&1; awk '/^dns:/,/^tls:/' /opt/adguard-docker/conf/AdGuardHome.yaml 2>&1 | head -60; awk '/^filters:/,/^whitelist_filters:/' /opt/adguard-docker/conf/AdGuardHome.yaml 2>&1 | head -80
sec "NEXTCLOUD SETTINGS"; docker exec -u www-data nextcloud php occ status 2>&1
for k in trusted_domains overwritehost overwriteprotocol overwrite.cli.url trusted_proxies datadirectory allow_local_remote_servers; do echo -n "$k: "; docker exec -u www-data nextcloud php occ config:system:get $k 2>&1 | tr '\n' ' '; echo; done
sec "FOLDER SIZES"; du -sh /home/$U/immich /home/$U/nextcloud /home/$U/750GB_HDD /mnt/storage/* 2>&1
sec "HOMEPAGE CONFIG (secrets masked)"; ls -la $HP
for f in services.yaml widgets.yaml settings.yaml bookmarks.yaml docker.yaml custom.js custom.css; do echo "### $f"; mask < "$HP/$f" 2>&1; echo; done
sec "HOMEPAGE RECENT ERRORS"; docker logs homepage --tail 80 2>&1 | grep -i -E "error|warn" | tail -12 | cut -c1-220
} > "$OUT" 2>&1
chown "$U":"$U" "$OUT"
echo "Saved: $OUT"
EOF
sudo bash ~/prodesk-full-report.sh
